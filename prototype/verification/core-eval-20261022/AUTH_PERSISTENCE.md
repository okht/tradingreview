# 本地 ChatGPT 授权持久化验收

日期：2026-10-22。用户明确要求持久化，以避免开发重启后重复授权。

## 实现

- Windows DPAPI CurrentUser 加密整个凭证记录，存于各 `HUIKAN_DATA_DIR/oauth-credentials.dpapi.json`；无明文回退，不读取其他应用凭证。
- 保留 SDK 刷新所需的 `clientId`、`scopes` 等字段。令牌旋转通过串行、原子写入保存；写失败保留旧记录且不报告保存成功。
- 取消登录保留已有授权；服务关闭等待已开始的持久化操作；主动「断开授权」串行清除凭证并停止当前分析请求。
- 同一数据目录只允许一个本地服务实例，避免多个进程同时轮换同一刷新令牌。不同数据目录独立。
- 设置打开只读取授权状态，已保存授权可直接验证模型；不会为状态检查重复启动登录或模型验证。
- 损坏、解密失败、存储失败均明确报错，原工作区材料保留。凭证和临时密文文件被 Git 忽略。

## 本机实际验收

1. 在隔离服务 `127.0.0.1:8791` 完成一次正常 ChatGPT 订阅授权，并通过 `gpt-6.1-sol` 连接验证。
2. 仅检查文件存在及大小：加密凭证文件存在，3771 字节；没有输出凭证内容。
3. 终止并重新启动该本地服务，使用同一数据目录。
4. `/api/oauth/status` 返回 `status=connected`、`persisted=true`，消息为「ChatGPT 授权已恢复，重启本地服务无需重复授权。」
5. 页面显示「使用已保存授权」，点击「验证并连接」后真实模型验证成功、弹窗关闭；此次未再打开授权页。

截图：`oauth-restored-after-restart.png`。用户原来的 `8788` 服务未重启；本次实际恢复验证针对 `8791`。
