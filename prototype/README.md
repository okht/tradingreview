# TradingReview / 投资决策复盘与学习

围绕「带着一个疑问进入 → 核对关键决定 → 留下可用经验 → 在下一次决策中试用」设计的 Agent 产品。

当前主入口是以对话为中心的 Agent 工作区。侧栏提供新建复盘、历史复盘、交易方法、检查项和设置；对话负责整理交易、确认候选、核对决策和保存经验。完整版从空工作区开始；快速体验版预载已完成的经典案例。两版使用同一产品界面与计算流程，均不挂载早期六步向导或 legacy 页面。模型请求通过 Pi 执行，扶摇历史日 K 的 REST 接入、官方 HTTP MCP 工具发现和事件原文录入已实现。

自动化验证使用真实 Pi 执行循环、模拟模型提供方与模拟金融接口。2026-10-21 已使用获准的扶摇凭证验证 10 根真实历史日 K，并通过自动取证工具保存 2 条真实资讯证据；详见 [金融连接验收](verification/2026-10-21-financial-connection.md)。模型订阅及其他外部服务的验证范围见 [AI 验证说明](docs/AI_VALIDATION.md)。

界面采用浅灰背景、两个白色圆角面板和左上角可选头像。侧栏支持折叠与拖动调整宽度，主区保留单列对话、底部输入框和共享交易 K 线。可见界面不展示品牌顶栏。公共组件基于 `@okht/huikan-design-system` 0.2.0，源码见 [Design System](https://github.com/okht/huikan-design-system)；本产品保留用户确认的局部样式。参考来源和实施记录见 [工作区调整](verification/2026-10-22-workspace-shell.md) 与 [控件调整](verification/2026-10-22-ui-controls.md)。

## 在线体验与版本说明

对应笔试平台的**第 2 题「投资决策复盘与学习」**。题目附件保留原文件编号 `11_投资决策复盘与学习.md`。

| 版本 | 可操作产品入口 | 使用方式 |
|---|---|---|
| 完整版 | [tradingreview.cht.me](https://tradingreview.cht.me/) | 连接自己的模型，导入或描述交易，完成背景、证据、AI 复盘、交易方法、回测与检查项流程 |
| 快速体验版 | [tradingreview.cht.me/quick](https://tradingreview.cht.me/quick) | 直接查看已完成的经典案例，编辑背景和检查项，选择已保存方法重新回测；继续发起新的 AI 对话时连接自己的模型 |

快速版首次打开会载入贵州茅台 `600519.SH` 的 20 笔模拟成交、15 分钟合成行情、已完成 AI 复盘、2 个交易方法版本、1 条检查项及同条件对照回测。股票身份真实，成交、价格、行情和用户背景均为构造数据；回测指标仅用于验证流程，不代表实际投资业绩。保留的 AI 回复来自实际 `gpt-6.1-sol` 验收运行，文本与证据快照原样保留；[来源清单](public/demo/quick-workspace-provenance.json)记录对应运行 ID 和数据摘要。预载内容没有模型连接或密钥，也不会在页面打开时自动调用 AI。首次载入后，刷新保留访客修改。

建议快速体验顺序：查看复盘及引用 → 展开「查看交易与材料」核对成交、K 线与背景 → 打开「交易方法」选择方法并运行回测 → 打开「检查项」编辑并保存 → 刷新确认保存。完整流程需要自己连接模型后导入交易开始。

公开入口使用签名访客 Cookie 识别浏览器，每位访客有独立的云端工作区。完整版与快速版分别使用独立的浏览器存储和服务端分区，彼此不覆盖。相同浏览器配置中的标签页共用该访客身份；不同浏览器或隐私窗口会获得另一工作区。清除网站数据会失去当前浏览器的访客身份和本机副本，不提供匿名工作区的跨设备找回。

**云端模型范围：**两版均提供模型 API 接入，由体验者在「设置 → AI 模型」填写自己的模型与 API Key。密钥仅保留在当前页面内存并经同源服务用于发起请求，刷新后需要重新连接。ChatGPT 订阅 OAuth 仍仅在本地服务中可用，公开云端入口不提供订阅登录。快速版的历史复盘可以直接阅读，产生新的 AI 回答仍需要连接模型。

## 本地运行

需要 Node.js 22.19+ 和 npm。进入本目录运行：

```sh
npm ci
npm run dev
```

开发命令同时启动前端和本地服务。前端默认地址为 http://127.0.0.1:5173 ，通过代理访问 http://127.0.0.1:8787 的 API。端口占用时以终端实际输出为准。

```sh
npm test
npm run build:local
npm start
```

- `npm test`：运行领域规则、旅程状态、前端服务、Pi 执行循环和服务端接口测试。
- `npm run build:local`：生成 `dist-local/` 前端产物。
- `npm start`：提供前端产物和本地 API，默认 http://127.0.0.1:8787 。本机工作区保存目录默认为 `.huikan-data/`，可通过 `HUIKAN_DATA_DIR` 设置。
- `npm run build`：生成云部署产物，使用 Vinext、Pi 和 D1；云端需绑定 `DB` 并配置部署环境。云端 OAuth 不可用，模型通过 API 连接。

Windows 本地服务将 ChatGPT OAuth 授权用当前 Windows 用户的 DPAPI 加密，保存在各自 `HUIKAN_DATA_DIR` 内；重启后自动恢复，令牌刷新也会写回。需要 PowerShell 7（默认从 PATH 查找 `pwsh.exe`，也可设置 `HUIKAN_PWSH_PATH`）。不会把令牌写入浏览器存储、工作区内容或日志；加密不可用时不降级为明文。设置中的「断开授权」移除本机保存的授权；取消登录和正常关闭服务保留已有授权。API 密钥仍只保留在当前页面的模块内存，刷新页面后需重新连接。密钥经同源服务用于用户发起的模型请求。模型名称必须明确选择或填写，界面不会猜测订阅默认模型。

工作区仅保存模型公开标识及通过白名单校验的无凭证接口地址。更换模型会更新会话的分析版本，交易、背景、历史消息和已保存检查项继续保留；旧回答的生成来源不能作为新模型的运行结果。

依赖版本由 `package-lock.json` 锁定。测试通过与浏览器验收结果应以实际执行记录为准，不能由本 README 推定。

## Agent 工作区

- **模型设置**：首次使用时，通过侧栏「设置」连接模型 API；本地版本另外支持订阅 OAuth。只有服务端验证成功才显示已连接；未配置模型时不能产生新的 AI 回复。快速版预载的历史回复单独保留生成模型和来源。
- **添加交易**：可以直接在聊天中描述交易，由模型整理为待确认候选；也可打开「导入交易」，上传或粘贴 CSV，或读取符合标准的只读账户接口。用户核对、补齐必要字段并确认后，记录才进入复盘材料。
- **导入后准备**：文件导入完成或在聊天中确认首批成交后，已连接模型会自动执行 `prepare`，每批 5 笔顺序整理背景候选并尝试读取已配置的相关证据，显示已完成笔数。每批保留整组已确认历史作为上下文。未连接时提示待连接；正在生成复盘回答时等待空闲。准备可停止，取消或失败后保留已完成候选与证据，可继续剩余成交；失败不会删除成交或阻止后续复盘。
- **确认背景**：理由和计划为空时显示灰色 AI 候选，按 Tab 或点击「采用」才写入背景；也可直接输入或忽略。没有候选时，Tab 保留正常焦点导航。已有文字、「记不清了」「当时没有计划」及已有原始记录内容不被候选覆盖。采用内容标为「现在回忆」，并保留「AI辅助草稿，经用户确认」出处；未提供原始记录时间的「当时记录」仍提示待核实。
- **连续复盘**：围绕具体疑问继续对话。缺少价格或费用时保留未知，缺少理由时继续补充背景。请求期间显示状态与工具执行信息，校验通过后呈现完整回复，失败支持重试与取消。
- **展开材料**：交易与 K 线、决策背景、相关证据可随时展开。可以选择复盘范围、切换关键成交、补充原始记录，并通过引用核对依据。主回复段、每条事实、每条解释和检查项各自保留证据编号，引用入口可查看该次回答使用的证据快照。材料变化会更新会话版本。
- **保存经验**：从回答中提取检查项，编辑名称、适用情境、动作和例外后保存。检查项保留来源会话、生成批次与证据编号，可在侧栏「检查项」中查看和修改。
- **管理历史**：「新建复盘」增加独立会话，已有交易、背景、对话和检查项继续保留。历史复盘可切换、重命名；已有交易的会话再次导入一批成交时，会为新数据创建复盘。

新生成的候选整理与复盘均使用已连接模型，完整版默认空工作区，快速版首次载入上述经典案例。用户也可显式导入标明合成来源的验证资料包；这类价格和行为不作为真实市场记录。自然语言中的缺失字段不会在确认环节自动补成事实。K 线仅开放已有数据支持的周期，常用周期偏好保存在本机。

背景准备读取当前会话这一组已导入成交及已确认背景、行情和证据，未采用候选与其他会话的历史消息不会进入准备请求。复盘回答按当前选中范围取材；跨会话批量回测仅在用户明确发起该操作时读取指定数据组。中途采用已完成批次的候选时，剩余准备暂停；继续后使用更新的确认背景，已完成笔数保留。普通材料编辑会收起原候选，需按当前材料重新准备。切换会话、修改材料、重新导入或取消后，旧准备结果不能写回新范围。500 笔是导入上限，分批准备的整体容量、耗时及真实输出质量仍需验收。

扶摇已实现官方历史日 K 接口调用与结构校验，需用户提供有效 API Key、明确带交易所后缀的 A 股代码和日期范围。成功返回的未复权行情可进入图表和复盘上下文；Pi 的 `read_market` 读取本次已提供的行情，区分决策前后材料并返回可引用证据，不会在该工具内重新联网验证来源。行情变化会使当前分析失效。

iFinD 和扶摇的 HTTP MCP 入口支持自动取证。在「设置 → 数据连接」连接官方 HTTP MCP 后，Pi 会调用实际发现且明确标为只读的工具，按标的、成交时点和决策背景查询支持与反面材料。结果保留原始字段、来源、公开时间与采集时间，自动关联成交并进入相关证据。未知公开时间保留未知；公开过不证明用户当时看到。未配置、未暴露只读工具或调用失败会明确显示状态，并保留已有复盘。临时凭证仅在当前页面内存和单次服务请求中使用；服务端默认连接由管理员配置。手动补充原文入口继续保留。

扶摇资讯 MCP 返回 404、405、501 时，可使用固定的官方个股资讯 REST 接口，页面会明确显示「官方资讯 API」。该接口按游标分页；尚未覆盖的历史时间范围继续标为待核对。模拟标的不会关联到真实股票新闻。

## 交易方法与历史验证

- 在对话中提出「提炼我的交易模式」「采用改进并保存」「保存原方法」「只采用第二条」或「回测工作区已有标的」，模型返回结构化操作，应用执行成功后才显示保存回执。
- 没有填写买卖理由也可研究：Pi 可提出规则候选，确定性工具核对当时已可知的行情特征，返回相符成交、反例、无法判断的成交和有信号未成交的节点。推断不会写回用户的理由或计划。
- 当前可执行规则支持单标的人民币股票多头的均线趋势、均值回归、投入比例、止损、止盈和最长持有期。仅能定性表达的经验进入检查项；复杂事件规则需进一步明确后扩展执行器。
- 改进候选与原方法分版本保存。采用并保存改进版时，同时保留对应的原版；两版通过校验后统一写入本机方法库，保存失败不显示成功回执。用户可只采纳指定约束；不预设改进必然提升收益。侧栏「交易方法」可选已有兼容行情和日期，批量回测并按收益、回撤或夏普排序，每页固定十项。
- 原方法与改进方法分别回放，只有方法版本、资金、成本和时间范围一致且两次计算均成功，才展示收益、回撤、费用等差额；实际历史成交作为独立参照保留。缺少原方法、资金或行情，以及任一回放失败时，比较显示不可用及具体原因。明确止损百分比与可执行规则不一致时会阻止采纳，不能用默认参数静默替代。
- 对比使用相同起始资金和时间范围。起始资金必须明确提供；模拟默认手续费为成交额万分之三、滑点万分之五，最小买入单位为一百股，均可修改。实际成交按原始价格和记录费用核算，缺失费用、本金不够、缺少期初持仓或对应行情时停止比较并说明原因。
- 信号只基于已完成且可获得的 K 线，下一可用开盘执行；遵守 T+1、现金和持仓约束。期末按收盘价估值，含未实现盈亏。当前不模拟最低佣金、印花税细分、涨跌停流动性、分红拆股或市场冲击，结果同步显示这些计算边界。
- 「推导期之后」表示日期关系，严格的独立验证还要求规则冻结前未看过这段行情。批量排名保留样本选择偏差提示，不能将历史差额作为未来收益承诺。

接口 `POST /api/research` 返回确定性计算报告；原始行情与真实模型密钥均不由模型生成。金融行情目前接入扶摇完整日线，以及用户明确导入的合成观测。合成观测支持 15 分钟、4 小时、日、周、月图表；声明 `reviewInterval: '15m'` 的资料包向 AI 提供同口径的 15 分钟行情工具。15 分钟 OHLC 来自独立的 5 分钟合成观测，不代表真实逐笔市场极值。真实股票代码与合成价格分别标记。公开的合成文件用于功能验证，报告明确标注合成行情；未接入真实 15 分钟行情。

## CSV 导入

在「导入交易」弹窗中选择 CSV 文件、粘贴内容或下载空白模板。模板只含以下八列表头，没有预置成交。先检查数据，再确认交易。核算按单账户、单标的设计，完整周期盈亏要求从空仓到清仓；CSV 没有账户列，请先在导出文件中筛选账户。

```csv
id,symbol,name,time,side,quantity,price,fee
```

| 字段 | 规则 |
|---|---|
| `id` | 非空、每笔成交唯一 |
| `symbol` / `name` | 非空；本次仅支持一个标的 |
| `time` | 中国本地时间，例如 `2025-09-08T10:00`；可含秒，不接受纯日期、`Z` 或时区偏移 |
| `side` | `buy` 或 `sell` |
| `quantity` | 正数，单位为股 |
| `price` | 正数，人民币元 |
| `fee` | 非负数，人民币元；无费用也须填 `0` |

采用 UTF-8、逗号分隔 CSV；文件选择上限 1 MB，最多 500 条。所有字段必填。解析使用 PapaParse，可处理引号、逗号和引号内换行。缺列、重复列、重复成交、非法日期或数值会阻止整批字段导入。

未清仓、超卖、期初买入缺失或多个周期时，不报告完整周期净盈亏和收益率。字段校验与周期完整性核算各自保留边界。已有交易的会话导入新数据时创建另一份复盘，已有资料继续留在历史会话。编辑交易允许暂缺价格或费用，此时相关金额显示待补充或待核对；CSV 初次解析仍执行上表的必填规则。

用户导入 CSV 只有成交记录，缺少开、高、低、收；补充行情前图表显示「行情待接入」，不会从成交价推造 K 线。图表仅开放已有数据支持的周期，决策时点与后续信息分开呈现；扶摇当前接入的粒度为日线，不会把日线拆分为分钟行情。

### 计算口径

- 净盈亏＝卖出成交额－买入成交额－全部费用。
- 投入收益率＝净盈亏÷（累计买入成交额＋买入费用）。
- 每笔成交金额及费用按十进制四舍五入到分，再汇总；持仓数量使用整数缩放计算，保留小额残余。
- 仅报告一个完整多头周期；不年化，不处理分红、拆股、汇率、融券或期末市值估算。

## 只读账户接口

账户入口支持管理员配置的通用 HTTP JSON 数据源。当前未内置任何交易所或券商适配器。服务端 `ACCOUNT_API_HOSTS` 必须列出允许访问的精确域名，多个域名用逗号分隔；缺省为空，此时界面明确提示尚未配置。示例配置：

```powershell
$env:ACCOUNT_API_HOSTS = 'trades.example.com'
npm start
```

用户填写 HTTPS 接口地址，可填写可选的 Bearer Token。前端向同源 `POST /api/account-trades/preview` 提交 `{endpoint, token?}`，服务端仅向允许的域名发起 GET，不跟随重定向。URL 不接受用户名、密码、片段或凭证查询参数；响应限 1 MB，超时 10 秒。Token 使用输入控件与当前请求传递，不写入日志、浏览器存储或工作区。此入口不发送下单请求。

接口必须返回 `application/json`，使用以下结构：

```json
{
  "currency": "CNY",
  "quantityUnit": "share",
  "assetType": "stock",
  "trades": [
    {
      "id": "T-001",
      "symbol": "600000",
      "name": "接口返回的股票名称",
      "time": "2025-09-02T09:45",
      "side": "buy",
      "quantity": 100,
      "price": 40,
      "fee": null
    }
  ]
}
```

支持单账户、单标的、人民币计价、数量单位为股的股票成交，最多 500 笔；接口提供方需先筛选账户。每笔成交的八个字段都必须出现，`price` 和 `fee` 可显式为 `null` 以保留未知，不会把缺失费用补为 `0`。其余字段沿用 CSV 的类型与时间规则；重复成交、混合标的、其他币种或资产类型会拒绝导入。读取成功后仍需用户预览并确认，才会替换当前复盘交易。

## 数据保存与边界

金融数据连接支持服务端配置。本地运行时从 Git 忽略的 `.env.local` 加载 `FUYAO_API_KEY`，`FUYAO_MCP_URL` 默认使用官方资讯服务；也可按官方配置填写 `IFIND_MCP_URL`、`IFIND_API_KEY` 和 `IFIND_AUTH_HEADER`。线上使用同名运行时 Secret，并必须设置 `FINANCIAL_OWNER_ID` 为允许使用连接的账户 ID。凭证不会进入前端包、工作区或分析记录。

设置里的「服务端已配置」仅表示配置存在；点击验证后才显示可调用的只读工具数量。日 K 查询与自动取证分别验证，日线可用不代表已获取事件原文。临时页面连接仍可用于其他账户，刷新后会清除该临时凭证。

当前工作区采用版本 2，浏览器键为 `huikan.agent.workspace.v2`，保存独立会话的交易、范围、已确认背景、行情、事件、取证状态、消息、聊天草稿、待确认成交候选与检查项。自动准备产生的未采用背景候选只保留在页面内存，刷新后清空，进行中的准备不自动恢复；已采用文字、AI 辅助出处和已保存证据继续保留。刷新后可手动点击材料栏「准备背景与证据」重新准备，未连接模型时进入连接设置，刷新本身不会重新发起 AI 请求。导入弹窗中的预览、未提交编辑和凭证不属于跨刷新保存范围。保存失败或恢复冲突会明确提示。

快速版使用浏览器键 `tradingreview.quick.huikan.agent.workspace.v2`，请求携带 `x-tradingreview-mode: quick`，服务端按已验证的访客身份进一步分区。完整版使用 `full` 分区。云部署需要 D1 的 `DB` 绑定与至少 32 字符的服务端 `VISITOR_SESSION_SECRET`；该密钥用于签名访客身份，不能提交仓库或发送至前端。

版本 2 最多容纳 30 个会话、每会话 200 条消息和 500 笔成交、300 条检查项，序列化工作区上限为 900 KB。所有保存均经结构校验。原记录无法读取时先保留原始内容，界面提供备份后继续的处理入口。

首次发现旧 `huikan-journey-prototype-v1` 时，只迁移能识别为真实导入的一次复盘，以及可以关联到真实分析批次的检查项；不会迁入构造示例。旧键不被删除或改写，并非所有历史演示状态都进入新工作区。更早的 `huikan-prototype-v1` 不自动迁移。K 线偏好仍使用 `huikan-chart-preferences-v1`。

工作区可通过同源接口自动保存至本地服务文件或云端 D1，保存已有数据不要求连接模型。空白且尚未使用的本机工作区可自动恢复同一访客的服务端记录；本机已有不同内容时，用户明确选择恢复服务端或使用本机。冲突与网络失败不静默覆盖本机记录。凭证不属于工作区数据。不同域名和端口的浏览器存储独立，清除网站数据会移除本机副本。

确认导入会触发一次背景与证据准备；之后的模型追问和复盘由用户发送问题触发。请求仅发送对应任务的材料。当前不做自动交易、检查项语义匹配或投资收益承诺。模拟模型测试不能证明投资判断准确率或学习效果；真实金融账号权限、数据覆盖、公告真实性与模型生成质量仍需独立验收。
