# AI 使用与验证记录

项目：TradingReview / 第 2 题「投资决策复盘与学习」。记录日期：2026-10-22。

## 使用方式与责任范围

我使用 Codex 辅助完成方案梳理、代码实现、数据构造、测试、网页验收、演示制作和部署。我在协作中明确产品任务、展示要求与优先级，持续纠正理解偏差；代码实现和自动化验证由 AI 工具执行，最终交付保留其可复核记录。

| 工具 / 模型 | 参与环节 | 验证边界 |
|---|---|---|
| Codex | 阅读题面和源码、实现前后端、生成模拟数据、自动测试、浏览器操作、PPT/Slidev 制作、打包部署 | 工具执行结果与截图作为证据；没有将 AI 自述的完成情况直接当成验收通过 |
| ChatGPT 页面「Pro」 | 对早期产品方案提出评审意见，包括从具体疑问进入、区分过程与结果、避免强制总结教训 | 当时页面只明确显示「Pro」，不进一步推断底层型号；该咨询属于设计建议 |
| 产品内真实 `gpt-6.1-sol` | 通过已授权的本地 ChatGPT 订阅执行背景建议、复盘与检查项生成 | 真实运行输入、输出、失败和模型标识保留；只对所测案例作结论 |
| 受控假模型 / HTTP 响应 | 测试 Pi 工具循环、坏输出拒绝、取消、接口失败、数据缺失和保存边界 | 用于可重复验证工程行为，不用于计算真实模型回答质量 |

未把个人模型授权、API Key、账户 Token 或真实持仓放入公开源码、快速案例或提交包。快速案例由构造交易和已记录的验收回复组成，来源见 [预载内容清单](../prototype/public/demo/quick-workspace-provenance.json)。

## 我明确提出并推动的修正

| 问题或偏差 | 我的修正要求 | 形成的结果与证据 |
|---|---|---|
| 方案把学习闭环收窄为保存方法 | 除保存外，还要让 AI 建议改进方法，并沉淀可执行检查项 | 两个方法版本、同条件回测和可编辑检查项均进入经典链路；[M04–M07](03_测试说明.md) |
| 背景建议被表达成框外的「AI 待确认稿」或提问 | 在理由/计划输入框里显示对当时动机和计划的灰字推测，按 Tab 采用，减少输入 | 输入框内建议、Tab 采用和 Esc 忽略完成页面验证；[原始交互结果](../prototype/verification/core-eval-20261022/inline-prediction-live-verification.json) |
| 评测工作有过度扩展趋势 | 先保证上手可跑的高频经典链路，再优化效果；必需覆盖主链路、缺失/失败和极端/合规 | 测试说明按三类场景组织，保留真实失败、修复与局限；[测试说明](03_测试说明.md) |
| 演示使用了与真实产品不一致的重画页面，截图清晰度不足 | 使用助手从真实关键页面自行截图，保持正确比例、高清 PNG、圆角与阴影 | 演示源保留原始 3840×2160 PNG；PPT 与即开 HTML 随包提供 |
| 模拟数据可能前后不一致 | 使用真实交易标的、丰富情境、40–50 组数据、每组 20–40 笔，最细 15 分钟；报告与数字保持逻辑一致 | 10 个真实 A 股标的 × 5 类情境，50 组、1,500 笔成交、16,000 根 15 分钟 K 线；[数据清单](../prototype/evaluation/fixtures/equity-50/manifest.json) |
| 反复连接订阅拖慢验证 | 先持久化本地授权，再继续主链路验证 | Windows DPAPI 加密保存与重启恢复已验证；[授权持久化记录](../prototype/verification/core-eval-20261022/AUTH_PERSISTENCE.md) |
| 评审者打开产品仍需要从空白开始 | 分为完整版与快速体验版；快速版预载案例，新 AI 任务由体验者自行连接模型 | 两个公开入口，独立保存与访客隔离；[云端验证](../prototype/verification/cloud-delivery-20261022/api-verification.json) |

这些条目来自本次协作中的明确指示与后续验证。下节的程序性缺陷主要由 Codex 在测试中定位，修复实现和自动复测也由工具执行，不将其全部归为我独立编写或独立发现。

## 工具发现的高优先级缺陷与复测

| 缺陷 | 修正与验证 | 证据 |
|---|---|---|
| 20 笔分为 5 个完整周期时，汇总工具把总净盈亏返回为空 | 扩展完整多周期核算，保留账户本金未知时的收益率未知；同一句真实模型问题复测得到净盈亏 82,179.41 元、费用 3,115.59 元，与独立 oracle 一致 | [修复记录](../prototype/verification/core-eval-20261022/multi-cycle-fix/REPORT.md)、[前后真实输出](../prototype/verification/core-eval-20261022/core-results.json) |
| 顶层回复可绕过引用/时点校验，合法引用 ID 可搭配错误金额或心理归因 | 主回复与学习项独立关联证据；部分交易数值回到原始字段和确定性计算；增加事后信息、回忆、合成材料边界检查 | [28 条挑战与修复](../prototype/verification/ai-contract-eval/README.md)、[修复后结果](../prototype/verification/ai-contract-eval/after-2026-10-22.json) |
| 合成案例调用真实公司新闻会混淆模拟行为与真实事实 | 合成情境的取证限定于资料包提供的合成证据，并公开提示材料边界 | [首轮失败与处理过程](../prototype/verification/core-eval-20261022/README.md) |
| 回忆类背景可能导致校验误拦，未来检查项也受影响 | 区分来源复述、历史因果断言与未来检查动作；保留谨慎的事实陈述和可编辑检查项 | [B04、M06](03_测试说明.md)、`prototype/tests/review-temporal-language.test.mjs` |

每轮修复保留原始失败。自动测试通过只证明覆盖的代码分支或构造输入符合预期；任意自然语言输出的事实真实性、引用支持程度、动机推测质量仍需要实际模型与人工评审。
